# 🗞️ Issue #014: Just Use Postgres: One Database to Replace Half Your Stack

![The Terminal Thursday](https://images.vialoops.com/cmpfndk6x026w0jvslad39ftq/cmv8yi3q00f3w0j044w2njxiz.jpg)

Every feature request adds a box to the architecture diagram: Redis for jobs, Elasticsearch for search, a vector database for embeddings, Kafka for events. Each box brings its own backups, auth and 3 a.m. failures, plus a second copy of data your database already holds. Meanwhile Postgres extensions can run queues, search, vectors and schedulers inside the same transactions and backups as your tables. This issue is Postgres first, with exit criteria, and a plain note on where Kafka, Elasticsearch and vector databases still win.

Grab your coffee. Open your terminal. Let's start hacking.

## 🔬 The Sandbox: 3 Projects I Tested This Week

### 1. pgvector 🧭 *(Vector Search)*

![pgvector](https://images.vialoops.com/cmpfndk6x026w0jvslad39ftq/cmw1w1cbh2shb0jyoefc70kmq.png)

**What is it?** pgvector is a Postgres extension written in C, under the PostgreSQL License, that adds a `vector` column type and distance operators such as `<->` for L2 and `<=>` for cosine, on Postgres 13 and newer. Search is plain SQL and exact by default, and an HNSW or IVFFlat index trades some recall for speed. The Get Started line assumes a running Homebrew `postgresql@17` or `postgresql@18`, the only two the formula covers, and opens psql, where `CREATE EXTENSION vector;` switches it on for that database (the README also documents an official Docker image, `pgvector/pgvector`).

**Why you should care:**  
Embeddings sit next to the rows they describe, so one query can mix similarity, a `WHERE` clause and a `JOIN` inside one transaction, and the README lists replication and point-in-time recovery through the write-ahead log, so no sync job has to keep a second database honest. Read the limits first: approximate indexes filter after the index scan, so with the default `hnsw.ef_search` of 40 a filter that matches 10% of rows returns about 4 results on average (iterative scans, added in 0.8.0, address that), and indexes stop at 2,000 dimensions for `vector` and 4,000 for `halfvec`. Past one machine the README says to scale up, then add replicas or shard with Citus or PgDog, and that is the point where a purpose-built vector database earns a look.

**My Rating:** Vendor-Free Vectors 4.8/5 ⭐  
**Website:** [github.com/pgvector/pgvector](https://github.com/pgvector/pgvector)

**💻 Get Started:**

```
brew install pgvector && psql postgres
```

### 2. PostgREST 🔌 *(Database to REST API)*

![PostgREST](https://images.vialoops.com/cmpfndk6x026w0jvslad39ftq/cmw1w1lgh2sh00jyz3h8tg279.png)

**What is it?** PostgREST is a web server written in Haskell, under the MIT license, that serves a REST API straight from an existing Postgres database. You point it at a schema and it turns the tables, views and functions there into endpoints (a function is called with a POST to `/rpc/function_name`), pushing as much work as possible into the database, including serializing the JSON response in SQL. Authentication is a JWT whose role claim makes PostgREST switch to the database role of that name for the length of the request, so Postgres roles and privileges, not controller code, decide who can do what.

**Why you should care:**  
Anything in the exposed schema becomes an endpoint without a controller, a serializer or an ORM model, the constraints in your schema stay the single source of truth for validation, and the OpenAPI description it generates feeds tools like Swagger UI. The docs recommend exposing views and functions instead of raw tables, so the schema you publish can change shape without breaking clients. The trade-off is that your business rules now live in SQL functions, views and constraints, so a team that wants them in TypeScript or Go is better served by a conventional app server in front of Postgres.

**My Rating:** The Controller-Free Zone 4.6/5 ⭐  
**Website:** [github.com/PostgREST/postgrest](https://github.com/PostgREST/postgrest)

**💻 Get Started:**

```
brew install postgrest && postgrest --example
```

### 3. PGlite 📦 *(Embedded Postgres)*

![PGlite](https://images.vialoops.com/cmpfndk6x026w0jvslad39ftq/cmw1w1mut2q4z0jy7bjci5yim.png)

**What is it?** PGlite is Postgres compiled to WebAssembly and packaged as a TypeScript library by Electric, so it runs in Node.js, Bun, Deno or a browser with no other dependencies, and the README puts it at about 3 MB gzipped. The README says there is no Linux virtual machine involved, and because WebAssembly can't fork processes, it uses Postgres' single-user mode and talks to it through an input/output pathway from JavaScript. Databases can live in memory, on the file system or in IndexedDB, extensions such as pgvector and PostGIS are supported, and the license is your choice of Apache 2.0 or the PostgreSQL License.

**Why you should care:**  
Tests and local-first apps get a Postgres engine in-process, started with `new PGlite()`, so the test database stops being a different engine that disagrees with production about edge cases. The limit is in the README: PGlite is single user and single connection, which makes it a fit for tests, prototypes and apps that embed their own database, and not a stand-in for a server with a pool of clients. The README also carries an alpha status badge, so pin your version and check the docs before you build a product on it.

**My Rating:** Pocket Elephant 4.7/5 ⭐  
**Website:** [github.com/electric-sql/pglite](https://github.com/electric-sql/pglite)

**💻 Get Started:**

```
npm install @electric-sql/pglite
```

## ☕ The Curious Non-Dev: No Code Required

**What is a database extension, and how can one database replace five services?**

Think of Postgres as a stand mixer. The motor does the hard, valuable work: storing data durably, making every change all-or-nothing, and recovering after a crash. An extension is an attachment that clicks onto that motor. Technically, `CREATE EXTENSION` runs a script that adds new building blocks to one database, such as data types, functions, operators and index support, and it records them so the whole bundle can be removed again. One attachment teaches the database to compare embeddings, another runs jobs on a schedule, another adds a message queue, and all of them borrow the same motor, the same backups and the same permissions.

So how does one database replace five services? Each of those services is mostly an attachment that arrived with its own motor: its own storage, crash recovery, accounts and backups. Fold the attachment into the database you already run and the spare motor goes away, along with the awkward moment where two systems disagree, because a queued job and the order it refers to can be saved in one transaction or not at all. The caveat is that a few jobs need a bigger machine than any attachment. Kafka spreads topics across servers and Elasticsearch spreads an index across a cluster. When you need that, you stop attaching and buy the industrial mixer.

## 📡 The Radar: 12 More Boxes to Delete From Your Diagram This Weekend

### 🧩 Extensions That Replace Services

1. [citusdata/pg_cron](https://github.com/citusdata/pg_cron) (~3.9k Stars) - A job scheduler that runs inside Postgres as an extension: cron syntax or an interval of 1 to 59 seconds, jobs stored in a cron.job table, and a rule that two runs of the same job never overlap.
2. [pgmq/pgmq](https://github.com/pgmq/pgmq) (~5.4k Stars) - An SQS-style message queue built from plain Postgres SQL objects, with no background worker, exactly-once delivery within a visibility timeout, and archiving instead of deletion when you want replay.
3. [paradedb/paradedb](https://github.com/paradedb/paradedb) (~9.5k Stars) - The README's own tagline is "Just use Postgres," and it ships a Rust extension with a custom index for BM25 full-text and vector search, plus filters and aggregations; the community edition is AGPL-3.0.
4. [postgis/postgis](https://github.com/postgis/postgis) (~2.3k Stars) - Adds GIS simple features, R-tree indexing and a long list of spatial functions to Postgres; this GitHub repo is a mirror, and the project's official home is at OSGeo.

### 🛠️ Migrations & Operations

5. [xataio/pgroll](https://github.com/xataio/pgroll) (~6.6k Stars) - A Go CLI for zero-downtime, reversible schema migrations that serves old and new schema versions side by side, backfills columns when needed, rolls back instantly, and works with RDS and Aurora.
6. [pgbackrest/pgbackrest](https://github.com/pgbackrest/pgbackrest) (~4.5k Stars) - Backup and restore for Postgres, written in C and MIT licensed, with parallel processing, lz4 and zstd compression, backups from a standby, multiple repositories and a custom protocol over TLS or SSH.
7. [ankane/pghero](https://github.com/ankane/pghero) (~8.9k Stars) - A performance dashboard for Postgres that starts with one docker run and a database URL, or mounts as a Rails engine, with query stats built on the pg_stat_statements module.
8. [dbcli/pgcli](https://github.com/dbcli/pgcli) (~13.4k Stars) - A Postgres client in Python built on prompt_toolkit, with context-sensitive auto-completion and Pygments syntax highlighting; on macOS it is one brew install away.

### ⚙️ Postgres as a Platform

9. [riverqueue/river](https://github.com/riverqueue/river) (~5.8k Stars) - A transactional job queue on Postgres or SQLite for Go, TypeScript, Ruby and Rust: jobs exist if their transaction commits, vanish if it rolls back, and stay invisible to workers until commit.
10. [graphile/worker](https://github.com/graphile/worker) (~2.4k Stars) - A Node.js job queue that uses LISTEN/NOTIFY to start jobs in milliseconds, per its docs, with cron tasks at minute granularity and delayed or debounced jobs; the README pairs it with PostgREST.
11. [neondatabase/neon](https://github.com/neondatabase/neon) (~23.3k Stars) - An open-source serverless Postgres platform written in Rust that separates storage from compute: stateless Postgres nodes sit on a Pageserver for storage and Safekeepers, a redundant WAL service.
12. [pgbouncer/pgbouncer](https://github.com/pgbouncer/pgbouncer) (~4.4k Stars) - A lightweight connection pooler written in C, with session, transaction and statement pooling modes and a documented default of about 2 kB of memory per connection.

## 🏗️ Closing Thoughts

This ecosystem leans on a friendly base license. Postgres says it is committed to staying free and open source and has no plans to change the PostgreSQL License, and a permissive base lets anyone ship an extension: pgvector, pgmq and pg_cron use that license, pgBackRest is MIT and PgBouncer is ISC. Not everything is that permissive, so read the terms before you wire something into a product, because ParadeDB's community edition is AGPL-3.0 and PostGIS is GPL. Every extension is also a dependency you upgrade in lockstep with Postgres, so check the supported versions before a major upgrade; PGMQ's README lists Postgres 14 to 18, for example.

The rule to steal isn't "never add a service." It's to add one on purpose, with a number in your hand. Pool connections early, watch your slow queries, and test your restores instead of trusting that backups exist. Then write down the limit that would make you move a workload out: events that many consumers must replay, a search cluster, a vector index that outgrew one machine. Postgres first, with an exit sign you wrote yourself.
