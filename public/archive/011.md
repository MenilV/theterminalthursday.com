# 🗞️ Issue #011: Night of the Living Forks: Open Source That Refused to Stay Dead

![The Terminal Thursday](https://theterminalthursday.com/img/issues/011/header_halloween.jpg)

It's Halloween week, so let's talk about the undead. Every few years, a company that grew up on community contributions decides its open-source license is bad for the quarterly numbers. The playbook barely changes: a blog post about the "evolution" of the licensing model, a new `LICENSE` file with words like "source available" or "Business Source", and a polite note that the code is still open—just not for your cloud provider, your competitor, or anyone who runs it as a service. Elastic did it in 2021. Lightbend did it to Akka in 2022. HashiCorp did it to Terraform and Vault in 2023. Redis did it in 2024.

Here's the part the boardroom keeps forgetting: you can't un-release code. Every version already published under an open license stays open forever, and a community with a `git clone` and a grudge can pick it up the next morning. This week is about the projects that clawed their way back out of the grave—forks that didn't just survive the funeral, but kept shipping releases long after the eulogies were written.

Grab your coffee. Open your terminal. Let's start hacking.

## 🔬 The Sandbox: 3 Projects I Tested This Week

### 1. Valkey 🧛 *(In-Memory Data Store)*

![Valkey](https://theterminalthursday.com/img/issues/011/valkey_og.png)

**What is it?** Valkey is a high-performance key-value data store forked from Redis 7.2.4 in March 2024, right before Redis switched to source-available licenses. It lives under the Linux Foundation with a BSD 3-Clause license, it was backed by AWS, Google and Oracle from day one, and it just shipped version 9.1.3.

**Why you should care:**  
Valkey speaks the same RESP protocol and the same commands, and it still answers `INFO` with `redis_version:7.2.4`, so redis-py, ioredis, Jedis and every other client library keep working without a single code change. If Redis is your cache, session store or job queue, swapping the binary is the cheapest license insurance you'll ever buy.

**My Rating:** Undead Throughput 4.8/5 ⭐  
**Website:** [github.com/valkey-io/valkey](https://github.com/valkey-io/valkey)

**💻 Get Started:**

```
brew install valkey && valkey-server --daemonize yes && valkey-cli ping
```

### 2. OpenTofu 🧟 *(Infrastructure as Code)*

![OpenTofu](https://theterminalthursday.com/img/issues/011/opentofu_og.png)

**What is it?** OpenTofu is the community fork of Terraform, started in August 2023 after HashiCorp moved Terraform 1.6 and later to the Business Source License. It's a Linux Foundation project under MPL 2.0 that runs your existing `.tf` files, modules and providers, and it has since shipped features Terraform users had been asking for for years, like client-side state encryption.

**Why you should care:**  
Your infrastructure code is the last thing you want held hostage by a license change. For most projects, migrating means installing `tofu` and running `tofu init` inside your existing Terraform directory—no rewrite, no new language, and the plan you get should look exactly like the one you had yesterday.

**My Rating:** Drop-In Necromancy 4.9/5 ⭐  
**Website:** [github.com/opentofu/opentofu](https://github.com/opentofu/opentofu)

**💻 Get Started:**

```
brew install opentofu && tofu init && tofu plan
```

### 3. OpenBao 👻 *(Secrets Management)*

![OpenBao](https://theterminalthursday.com/img/issues/011/openbao_og.png)

**What is it?** OpenBao is the community fork of HashiCorp Vault, built from the last MPL-licensed code after Vault 1.15 and later moved to the Business Source License. It stores and hands out secrets, certificates and encryption keys behind policies and audit logs, it's developed under the Linux Foundation umbrella, and its CLI is simply called `bao`.

**Why you should care:**  
Secrets management is the worst possible place for a license surprise: it sits in every deploy pipeline, every CI job and every service's startup path. OpenBao keeps the Vault model you already know—the KV engine, policies, the same `/v1/` API paths—under MPL 2.0, and `bao server -dev` gives you an unsealed, in-memory server for local testing in one command.

**My Rating:** Ghost in the Keychain 4.6/5 ⭐  
**Website:** [github.com/openbao/openbao](https://github.com/openbao/openbao)

**💻 Get Started:**

```
brew install openbao && bao server -dev
```

## ☕ The Curious Non-Dev: No Code Required

**If a company owns the code, how can anyone fork it and keep it free?**

An open-source license is a promise attached to a specific version of the code. When a company changes its license, it can only change the terms for future versions—everything it already published under the old open license stays open forever. A fork is simply a group of people taking that last open version, giving it a new name (the trademark stays with the company), and continuing the work from there. Think of a recipe printed in a cookbook: the publisher can stop printing new editions, but it can't take back the copies already sitting on everyone's shelves.

The surprising part is how often the forks win. The companies that depend on a project—cloud providers, Linux distributions, banks—usually prefer one run by a neutral foundation, so they move their engineers and their money to the fork. And that pressure works: Elastic added the open-source AGPL license back to Elasticsearch in 2024, and Redis did the same in 2025.

## 📡 The Radar: 12 More Forks to Raise This Weekend

### 🦇 Escaped from Oracle's Crypt

1. [MariaDB/server](https://github.com/MariaDB/server) (~8.5k Stars) - Monty Widenius's fork of MySQL, started in 2009 as Oracle moved to buy Sun, and now the MySQL-compatible server most Linux distributions ship by default.
2. [LibreOffice/core](https://github.com/LibreOffice/core) (~4.6k Stars) - The Document Foundation's 2010 fork of OpenOffice.org, created when most of the community walked away from Oracle; the office suite nearly every Linux desktop ships today.
3. [jenkinsci/jenkins](https://github.com/jenkinsci/jenkins) (~26.7k Stars) - Hudson's community renamed the project Jenkins in 2011 after a trademark dispute with Oracle, and the fork became one of the most widely deployed CI servers on the planet.
4. [illumos/illumos-gate](https://github.com/illumos/illumos-gate) (~1.9k Stars) - The OpenSolaris kernel and core userland, kept alive after Oracle shut OpenSolaris down in 2010; it still powers OmniOS, SmartOS and OpenIndiana.

### 🧛 The Relicensing Undead

5. [opensearch-project/OpenSearch](https://github.com/opensearch-project/OpenSearch) (~13.9k Stars) - AWS's 2021 fork of Elasticsearch 7.10 after Elastic dropped Apache 2.0, now governed by the OpenSearch Software Foundation under the Linux Foundation.
6. [apache/pekko](https://github.com/apache/pekko) (~1.7k Stars) - The Apache Software Foundation's fork of Akka 2.6, taken just before Akka adopted the Business Source License; actors, streams and clustering for Java and Scala.
7. [lxc/incus](https://github.com/lxc/incus) (~6.5k Stars) - The Linux Containers community's fork of LXD after Canonical took the project in-house in 2023, maintained by the same team that first created LXD; system containers and VMs from one CLI.
8. [OpenVoxProject/openvox](https://github.com/OpenVoxProject/openvox) (~0.2k Stars) - The Vox Pupuli community's build of Puppet, started in late 2024 after Perforce stopped publishing public open-source packages; effectively the same as Puppet, so existing manifests and modules keep working.

### 🧟 Community Coups

9. [neovim/neovim](https://github.com/neovim/neovim) (~103k Stars) - Started in 2014 to refactor Vim for async jobs, embedding and Lua plugins; the fork has since passed 100,000 GitHub stars.
10. [jellyfin/jellyfin](https://github.com/jellyfin/jellyfin) (~58.7k Stars) - Forked from Emby in 2018 after Emby went closed source; a free media server with no premium tier and no account required.
11. [nextcloud/server](https://github.com/nextcloud/server) (~37.3k Stars) - Forked from ownCloud in 2016 by its founder and core developers; self-hosted files, calendar, contacts and office under the AGPL.
12. [forgejo/forgejo](https://codeberg.org/forgejo/forgejo) (~5.7k Stars) - A community fork of Gitea started in 2022 after Gitea's domain and trademark moved to a for-profit company; a lightweight self-hosted Git forge with built-in Actions CI, hosted on Codeberg.

## 🏗️ Closing Thoughts

The license changes of the past five years were sold as protection against cloud giants freeloading on open source. In practice, the cloud giants were among the first to fund the forks—AWS built OpenSearch, and AWS, Google and Oracle lined up behind Valkey within days. The people left stranded were the volunteer contributors whose patches suddenly shipped under terms they never agreed to.

That's why the most important line in a project's README isn't the star count; it's who owns the copyright and whether contributors sign a CLA that lets one company relicense their work. A project governed by a neutral foundation can't be relicensed over a weekend. And the dead do come back, eventually: HashiCorp's own license turns every Terraform release back into MPL 2.0 four years after it ships, which means Terraform 1.6.0 rises from the grave in October 2027. Until then, the forks are doing the work—so send them a bug report, a sponsorship, or at least a star.
